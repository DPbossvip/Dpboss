# Result Hub — Render deployment (PHP + PostgreSQL)

This is a results-and-history portal, not a wagering product. It does not include betting, odds, predictions, deposits, withdrawals, wallets, or payment handling.

## Included
- Responsive market-results homepage and result-history page.
- Automatic market discovery from the configured API: no manual market count or market seed file is required.
- PostgreSQL schema auto-creation on first visit/sync.
- API sync via Render Cron Job every 15 minutes (adjust only to the provider's permitted rate).
- Idempotent upsert by market + result date to avoid duplicate daily records.
- Numeric-looking values are stored as strings so values like `08`, `03`, and `00` keep leading zeroes.
- Health endpoint at `/health.php`.
- Optional protected manual sync at `/sync-now.php` using `X-Sync-Token` header or `?token=`.

## Security — do this before deployment
The API key and domain key pasted into the chat and the credentials embedded in the supplied PHP kit should be considered exposed. Ask the API provider to rotate both keys. Do not reuse the old credentials and do not commit secrets to GitHub. Set the new values only in Render Environment settings.

## Important API check
The credential message gave `https://sattaapi.com/wp-json/satta/v1/results`, while the supplied PHP kit hardcodes `https://matkaapi.sattaapi.com/wp-json/satta/v1/results`. This project uses the first URL as a configurable default. Confirm the correct endpoint, HTTP method, JSON body, registered domain and permitted sync interval with the provider before enabling the cron job. If the provider confirms the other hostname, change `SATTA_API_URL` in Render.

## Render setup
1. Create a GitHub repository and upload the contents of this folder (not the parent folder).
2. In Render, create a **PostgreSQL** database. Copy its **Internal Database URL** if the web service and cron service are in the same Render region; otherwise use the External Database URL. Keep it private.
3. In Render, choose **New → Blueprint**, connect the GitHub repository and deploy `render.yaml`.
4. In the web service and cron service environment settings, set:
   - `DATABASE_URL` = the Render PostgreSQL connection URL
   - `SATTA_API_KEY` = newly rotated API key
   - `SATTA_DOMAIN_KEY` = newly rotated domain key
   - `SATTA_DOMAIN` = exact registered domain supplied by the provider (update after you attach your final custom Render domain if required)
   - `SATTA_API_URL` = provider-confirmed endpoint
5. Deploy. Visit `/health.php`; expected response is `{"ok":true,"database":"connected"}`.
6. Run the first sync manually from Render Cron Job → Manual Run. The homepage should populate markets from the API response.
7. Confirm market count against the complete API response. The JSON pasted in chat was truncated, so its complete market count cannot be inferred from that snippet.
8. Attach a custom domain only after the provider confirms the registered-domain change process. A domain mismatch can cause API authorization failure.

## Manual sync
Send a POST request with header `X-Sync-Token: <SYNC_TOKEN>` to `/sync-now.php`. Do not share the token publicly. The `SYNC_TOKEN` is generated by Render from the Blueprint.

## Notes / limitations
- The project auto-discovers every market returned by the API and stores market names and result values. It does not fabricate missing close values.
- A result row is keyed by market and the calendar date parsed from the provider's `date` timestamp. Confirm with the provider whether this timestamp represents the intended result date for overnight markets.
- API sync is scheduled every 15 minutes in the blueprint; change it to a slower cadence if your plan or provider subscription requires it.
- The initial version provides result display and history. It does not claim to be a pixel-perfect reproduction of DPBoss. Add your own brand identity and only use assets you have rights to use.
